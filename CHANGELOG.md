# Changelog

All notable changes to MAP. The CLI workspace packages are versioned in lockstep.

## Unreleased — AI Development Environment Manager

### Added

- `map detect`: Project Profiler for languages, frameworks, infrastructure, tooling,
  and coding agents across nested workspaces, with `confirmed`/`probable` evidence
  (`map.project-profile` v1).
- `map plan`: read-only configuration plan shared with `map init` (`map.plan` v1).
- `map skills list|search|info|suggest|add|install|update|remove|audit`: Agent Skills
  from Git or local sources, pinned in `.map/skills.lock.json` (lockfile v1), with
  structural validation, a heuristic content audit, and explicit approvals for
  scripts (`--allow-scripts`) and high-severity findings (`--allow-risky`).
- Development profiles (`webapp`, `api`, `wordpress`, `python`, `rust`, `ai-app`,
  `security-first`) and `map profiles`.
- `map sync --check` and `--force`; generated files carry a `map-sha256` hash.
- `map doctor` verifies installed skills against the lockfile.
- `MAP_HOME` and `MAP_OFFLINE` environment variables.
- ADR-0007 (proposed): Agent Skills management and trust model.
- Schemas and guides: project profile, plan, skills lockfile; project manifest v4.

### Changed

- `map init` now profiles the project, shows the plan, offers profiles and skills
  interactively, and validates the result. `--yes` applies only safe defaults.
- New workspaces target only the selected agents instead of all five; existing
  configs keep their targets. Use `--agents` to choose.
- `map.config.json` schema version 4 adds optional `agents`, `profiles`, and
  `skills.sources`. Versions 2 and 3 still load.
- **Behavior change:** `map sync` no longer overwrites instruction files MAP did not
  generate, or generated files edited by hand. It reports a conflict and exits 1;
  `--force` replaces them and keeps a `*.map-backup-*` copy. Files generated by
  earlier MAP versions are still regenerated.
- `--json` output from new commands goes to stdout without decoration.
- Help labels `analyze`, `recommend`, `patterns`, and `explain` as compatible names.

### Fixed

- `map add` rejects registry entries whose id or file names could escape
  `.map/patterns/` (a tampered registry cache could previously write elsewhere).
- `pnpm map` (running the CLI from TypeScript source) crashed on a parameter
  property; `erasableSyntaxOnly` now prevents this.

### Removed

- Unused `KnowledgeBase`/`InMemoryKnowledgeBase`, `NullRecommender`, plugin
  interface, rich `Pattern` type, and the placeholder `map diff` command.
- Nested `library/.github` and `tooling/.github` (GitHub never ran them); issue and PR
  templates, `SECURITY.md`, and `CODEOWNERS` moved to the root `.github/`.
- Planning and audit documents under `docs/project` and `docs/architecture`, replaced
  by `docs/architecture.md` and `docs/roadmap.md`; schema guides moved to
  `library/docs/schemas/`. History remains in Git.

## Architecture-layer MVP

### Added

- Product, system, pattern graph, scanner, recommendation, verification, CLI, MCP, and
  security architecture documentation.
- AI-focused ADRs for the deterministic core, stable pattern identity, versioned CLI
  JSON, static analysis, and MCP isolation.
- Pattern Schema v1 plus scan and recommendation result schemas with fixtures.
- `map list`, `search`, `show`, `scan`, `suggest`, `graph`, and `validate`.
- Evidence certainty and explicit static-analysis limitations.
- Registry snapshot freshness enforcement in CI.

### Changed

- The YAML reader now supports folded and literal block strings used by pattern
  metadata.
- README and library documentation now use the GitHub-only installation path and
  consolidated monorepo structure.
- Saved analysis reports use the versioned scan-result envelope.

### Compatibility

- `map patterns`, `explain`, `analyze`, and `recommend` remain supported.
- Pattern IDs remain `category/slug` for schema version 1.
- Existing flat `related` metadata remains valid and maps to `works_with` graph edges.

## CLI 0.5.1

### Added — the MAP context compiler (`.map` as the single source of truth)
- `map sync` — compile the markdown under `.map/` into every AI assistant's context
  file: `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursor/rules/map.mdc`, and
  `.github/copilot-instructions.md`. Generated files carry a "do not edit" banner.
- `map watch` — regenerate those outputs on every change under `.map/` (debounced).
- `map.config.json` gains `sources`/`targets` (schema v3, backward compatible: a v2
  config still parses and the compiler falls back to sensible defaults).
- Per-document selection via frontmatter (`targets`, `priority`).
- `map doctor` gains compiler checks: unsupported targets, sources matching nothing,
  duplicate sections, and broken references.

### Changed — the shared registry contract
- New package **`@missing-ai-patterns/registry`**: the single, canonical definition of
  the registry schema (types + `parseRegistry`), so the CLI, the website, and the
  registry builder can share one contract instead of three copies.
- The CLI re-exports the registry types from that package; no import paths changed.
- The registry download URL is now overridable via `MAP_REGISTRY_URL`, decoupling the
  published location from the content repository.

### Packages
- `@missing-ai-patterns/cli` 0.5.0 → 0.5.1
- `@missing-ai-patterns/score` 0.5.0 → 0.5.1
- `@missing-ai-patterns/registry` 0.5.1 (new)
